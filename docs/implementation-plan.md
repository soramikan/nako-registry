# 実装準備メモ

各作業は先行欄の成果を使う。仕様と入力は [仕様本文](specification.md)、[適合性フィクスチャ](../fixtures/v1/conformance.md) を参照。O 番号は [オーナーの判断と委任された詳細](open-questions.md) に対応する。

| ID | 対象リポジトリ・モジュール | 先行 | 完了条件 | 仕様・フィクスチャ |
| --- | --- | --- | --- | --- |
| P01 | `nako-registry` の共通仕様・schema・フィクスチャ | なし | 正本の版を固定して各処理系から参照できる。七つの schema と TOML の JSON 写像を再現可能に検証する。 | §1〜§5・§7、全サンプル、M-01〜08 |
| P02 | 共有 `nako-pkg-core` の ID・型・manifest 検証。利用側は `nako-registry`、`lnako` | P01 | ID、公開 SemVer、ハッシュ、target、SPDX、feature の循環、node-semver 7.7.4 の境界を検証する。ローカルと pack の必須欄を分け、識別可能な旧形式には新形式を案内する。 | §1〜§2、ID-01〜07、M-01〜08 |
| P03 | `nako-pkg-core` の Canonical ZIP、`lnako` の pack/verify | P02 | 全 kind の pack と厳格検証。同一入力を再ビルドして ZIP が一致する。独立ディレクトリ、欠落・破損、独自ライセンス本文の欠落を拒否し、アーティファクトごとの入口と native-source の ABI を検証する。 | §2〜§3、Z-01〜16 |
| P04 | `nako-pkg-core` のクロスアーティファクト検証 | P03 | 既定値・集合を正規化し、共通項目、導出したグローバル命令名、アーティファクトの重複を検証する。 | §3.3・§3.5・§5.3、X-01〜04・X-15/16 |
| P05 | `nako-registry` の Sparse Index 生成・匿名取得 | P01、P02 | config とパッケージ別 index を生成し、条件付き GET、キャッシュ制御、yank 状態、scope の不透明 ID を確認する。 | §1.1・§4、I-01/02、X-01・X-08・X-17、D-01 |
| P06 | `nako-registry` の scope 管理・OIDC 交換・公開権限 | P02 | 管理者による登録と移転を監査し、移転元の公開権限を失効させる。JWKS、対象パッケージの repository ID・workflow・保護済みタグを照合し、別 ID・別版への公開を拒否する。 | §1.1・§5.1、ID-04・ID-08、X-09・X-12・X-20 |

| P08 | `nako-registry` の yank とインデックス更新 | P05〜P07 | 対象パッケージを管理できる人だけが理由を付けて撤回できる。理由、監査、取得可能な既存バイト列、引き続き消費する容量を確認する。解除と同版の再公開は拒否する。 | §5.3・§6.2・§7、X-06・X-17/18、R-09 |

| P11 | `lnako` の公開 CLI と `nako-registry` の CI 統合試験 | P07、P08、P10 | 登録済み CI で一括公開し、状態照会で完了・反映待ちを区別する。索引取得、展開、yank、既存 lock の取得を通す。公開再送の 409 とレジストリ内部の再試行を別々に観測する。 | §3〜§7、X-01・X-06・X-08・X-17・X-19、R-09、T-01・T-02、D-01・D-06 |

共有ライブラリの実体の配置、Zig・Rust・JavaScript の接続方法は実装設計で決める。各利用側が同じ版のフィクスチャで同じ入出力を照合できることを、リポジトリをまたぐ依存の導入前に確認する。
