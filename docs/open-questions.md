# 判断記録と実装時に残る作業

O01〜O17 は仕様化時の論点。オーナーが対話で Q1〜Q38 を承認した。Q12 では「パッケージに利用実績がないため後方互換性は不要」と明示した。仕様上の扱いは [仕様本文](specification.md) を参照。

| 論点 | 確定した方針 | 実装時に残る作業 |
| --- | --- | --- |
| <a id="o01"></a>O01 正本 | nako-registry を正本とし、処理系ごとに参照版を固定する（Q1）。 | 参照版の配布と適合試験の実行方法を定める。 |
| <a id="o02"></a>O02 旧形式 | 旧 ID、manifest、ZIP、index、静的 PUT、lock の互換経路を設けない。識別可能な旧入力には新形式が必要だと診断する（Q12）。 | 拒否の診断と、新形式を手元で再作成する手順を用意する。 |
| <a id="o03"></a>O03 scope | 管理者が払い出しと移転を担当する。公開済み scope 名、Package ID、不透明な `scope_id` を維持する。移転元の権限を失効させて監査する（Q3・Q14・Q22）。 | 採番、登録・移転の操作、予約スコープの管理手順を設計する。 |
| <a id="o04"></a>O04 共通型 | 依存と engine の範囲は `node-semver` 7.7.4 の既定動作を基準とする（Q13）。公開時の `LicenseRef-…` は対応する本文の同梱が必要（Q36）。 | SPDX 一覧の固定版と本文の対応づけ、ターゲット集合、ABI 整数範囲、glibc・日時の細則を定義する。 |
| <a id="o05"></a>O05 マニフェスト変換 | ローカルでは公開用の ID・版・ライセンスを省略できる。配布用の pack と公開では必須。リリースの依存・engine・exports・feature を全配布物で共有し、依存の alias と global 許可を保持する（Q17・Q25・Q26）。 | glob、部分宣言の既定値、任意依存・feature の具体的な変換規則を定める。 |
| <a id="o06"></a>O06 Canonical ZIP | 同じ入力・pack の版・設定でバイト同一。他の生成器は正規形への適合を要する。独立ディレクトリエントリを禁止する（Q27・Q35）。 | 大小文字比較、許容する ZIP64 の細則、追加圧縮率の上限の要否と追加制御ファイルの扱いを定める。 |
| <a id="o07"></a>O07 native-source | ABI は `artifact.native.abi_version` に必須。ビルドはルートが Package ID と SHA-256 に対して明示許可した場合だけ。未許可なら universal に進み、代替がなければ診断する（Q7・Q18・Q29・Q34）。 | ビルド入力の呼び出し、許可の保存形式、CI での設定と生成物キャッシュを設計する。 |
| <a id="o08"></a>O08 クロス検証 | 共通エクスポートを比較し、アーティファクトごとのパスを許す。既定値を補い、集合の順序を無視して比較する。global エントリの `commands[].name` から命令名を導出する（Q17・Q28・Q32）。 | 各フィールドの比較単位と正規化を実装し、同名の識別と実ファイル照合の試験を加える。 |
| <a id="o09"></a>O09 公開確定点 | 検証失敗時は永続データ無変更。確定前の書き込み障害では公開状態を維持し、非公開の一時物を回収できる。DB 確定後は索引反映待ちを返せる（Q6・Q16）。 | 状態遷移、再試行と回収の安全性、障害時の観測・監視を実装する。 |
| <a id="o10"></a>O10 外部参照 | 初版は中央ホストへのアップロードのみ有効（Q4）。 | 外部参照の有効化、取得・保存の方式、運用上の URL 細則は後続の判断。クライアントの配信元検証は初版から適用する。 |
| <a id="o11"></a>O11 公開認証・状態照会 | 初版は登録済み repository ID・workflow、版に対応する保護済みタグでの GitHub Actions OIDC 公開に限る。認証付き照会で配信開始を確認し、待機上限では反映待ちを報告する（Q5・Q15・Q23・Q24・Q37）。 | タグ保護の確認方法、issuer/audience の設定、トークンの TTL と失効、応答形式と診断、multipart の対応を設計する。 |
| <a id="o12"></a>O12 名前解決・global | 未許可 global は既定でエラー。依存側の許可に加えルート側で同じ提供元を直接宣言し、許可する。global 版を選ぶ ID は単一版。scoped は共通版を優先し、同一メジャーでも複数版を許す（Q8・Q19・Q26・Q30・Q33）。 | alias の字句や通常依存とランタイム別依存で同じ ID を指定した場合の規則を定める。 |
| <a id="o13"></a>O13 lock | プロファイルごとの解決グラフ、ノードの ID・版・アーティファクトのハッシュを固定。同一ハッシュで許可された配信先なら URL は変えられる（Q20）。 | ノードキー、シリアライズ、初回解決の lock 書き込みとキャッシュの連携を設計する。 |
| <a id="o14"></a>O14 スキーマの拡張 | 同じ版の追加は、旧実装が無視しても挙動が変わらない任意項目に限る（Q9）。 | 既定値、命令の kind・型語彙、provenance、deprecated と advisories の詳細を実装時に定める。 |
| <a id="o15"></a>O15 yank | 人の管理権限でのみ実行し、理由は必須かつ公開。実行者と日時を監査する。初版では解除できない（Q10・Q31）。 | 人の認証、入力・応答、二重操作の扱い、索引反映の詳細を定める。 |
| <a id="o16"></a>O16 クォータ | ZIP 安全上限とは別に設定する。保管中は yank 済み配布物も scope 総容量に計上する（Q11・Q21）。 | **実測と予算がそろった段階で、ファイル、リリース合計、scope 総容量の具体値をオーナーが判断する。** |
| <a id="o17"></a>O17 非公開配布 | 初版は公開パッケージのみ。非公開配布は Issue #6 の後続設計（Q2）。 | 権限、認証付き取得、分離されたキャッシュの設計。 |

Q38 で、上の実装詳細は委任することを確認した。利用者から見える合意を変える必要があれば、実装で先に固定せず再確認する。

要件のサンプルは単体の構造例として保存している。`METADATA.toml` にある `./client` が `COMMANDS.json` にはないため、同じ ZIP に入れると §3.5 で拒否される。`engines` や `FILES.json` の長さ・ハッシュも個別の例示値。組み合わせて使う試験入力は [フィクスチャ一覧](../fixtures/v1/conformance.md) を参照。
