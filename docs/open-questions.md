# 未決定事項

表の選択肢は検討用。選択が必要になる実装単位は [実装準備メモ](implementation-plan.md) に記す。

| ID | 論点 | 選択肢・決める内容 |
| --- | --- | --- |
| <a id="o01"></a>O01 | 共通仕様・schema の恒久的な正本 | nako-registry、lnako、独立リポジトリのいずれを正本にするか。各処理系の取り込みと版の配布経路も決める。今回の配置先は nako-registry。 |
| <a id="o02"></a>O02 | 旧形式・静的配布からの移行 | 旧 ID・manifest・ZIP・index・PUT・lock をどこまで読み取りで並存させるか。旧ハッシュを保つ旧配信の併設、変換・再公開、互換期間を設けない切替が候補。アーカイブの再梱包ではハッシュが変わるため、旧 lock 保持が必要なら元のバイト列をどう残すか決める。 |
| <a id="o03"></a>O03 | scope の採番と所有権 | `scope_id` は UUID 系または別の不透明 ID。採番主体、予約スコープの特権登録、scope 名の変更・移転と権限引継ぎ、監査を決める。 |
| <a id="o04"></a>O04 | 共通型と範囲式の細部 | SemVer Range に現行 lnako の方言を採るか、別の互換文法を定めるか。SPDX リストの版と照合範囲、LLVM/Zig のターゲット集合、ABI 整数の範囲、glibc の比較単位、日時の表記と閏秒の扱いも確定する。 |
| <a id="o05"></a>O05 | manifest から配布物への変換 | ローカル専用 manifest の必須項目、部分的な `artifacts` 宣言の既定値、glob の規則、依存の `alias`・`allow_global_commands` と任意依存・既定 feature の配布形を決める。配布メタデータへの追加と、利用者側の情報だけで解決する方式を比較する。 |
| <a id="o06"></a>O06 | Canonical ZIP の残る正規形 | 明示的ディレクトリエントリを許すか、`NAKO-PKG/` をパス階層として扱うか。DEFLATE の再現性、ZIP64 の正当な利用範囲、大小文字の比較方法、圧縮率の独立上限、追加制御ファイル、参照パスの存在検査の範囲を決める。 |
| <a id="o07"></a>O07 | native-source の ABI とローカルビルド | index は `target.abi_version` を持つ。ソース用メタデータの ABI を `artifact.native.abi_version` に置くか、別の欄を使うか。ビルド入口、ツールチェーン、実行時の許可とキャッシュ契約を決める。 |
| <a id="o08"></a>O08 | クロス検証の比較と命令名集合 | 省略値と明示既定値や、配列の並び替えを等価とするかを明文化する。§5.3 の `global_commands` は §3.5 のサンプルに独立フィールドがない。global の `commands[].name` から作る集合の正規化と定数の扱い、種別間での `entry` の意味を決める。 |
| <a id="o09"></a>O09 | 公開確定点・失敗時の回復 | §5.3 の無変更条件と、S3/R2 → DB → index の順序・リトライを両立させる。非公開の仮状態を経由する方式と補償処理の方式を比較する。書き込み開始後の障害、競合、応答消失、索引反映待ちの応答、孤立オブジェクト、監視を定義する。 |
| <a id="o10"></a>O10 | 外部参照の公開と URL ポリシー | 初期は無効化、または管理者承認で開放。外部 ZIP の取得主体・保存有無・上限、HTTP リダイレクトの許否、ポートやホストの扱い、外部参照と中央 upload の組み合わせを決める。§5.1 は中央 upload が一つ以上と定める。 |
| <a id="o11"></a>O11 | OIDC・公開応答の詳細 | issuer、audience、許可 ref/workflow、トークン TTL と失効、手動トークン発行、旧 attestation の併用要否を決める。公開と交換の要求・応答形式、`409` 以外のコード、multipart ファイル名の対応と重複扱い、公開状態照会と dry-run の扱いも決める。 |
| <a id="o12"></a>O12 | 省略名・global の診断と名前解決 | 未許可 global を既定でエラーまたは厳格警告にする。alias の字句、runtime 依存と通常依存の同一 ID の扱い、間接パッケージ自身の名前解決、同一 ID 内で global 属性が版によって変わる場合、同一メジャーの複数版の扱いを決める。 |
| <a id="o13"></a>O13 | `nako.lock` の新レイアウトと更新 | ID と版を複合キーにするか、解決ノードに ID を付けるか。複数版・プロファイル・選択したアーティファクトの記録や、初回解決時に lock 用ハッシュを確定する時点を決める。旧 lock の読み取りは O02。 |
| <a id="o14"></a>O14 | ドラフト schema の必須性と拡張 | サンプルから構造を読める一方、manifest 内側の任意欄、METADATA の省略時値、命令の kind と型語彙、provenance の必須 claim、`deprecated`、`advisories` の完全な型は未確定。未指定の欄を閉じるか、版付き拡張を許すか決める。現ドラフトは manifest のトップレベルとランタイム名の表を閉じ、ほかは本文にない入れ子の追加フィールドを原則許容する。 |
| <a id="o15"></a>O15 | yank API の詳細 | §7 の POST を基に認証範囲、理由の必須性、繰り返し操作の応答、解除の可否と監査を決める。§6.2 の新規解決除外と既存 lock の例外は確定。 |
| <a id="o16"></a>O16 | クォータの値と計上範囲 | 総容量・リリース合計・個別ファイルの上限値、外部参照・yank 済みの計上、調整単位を決める。ZIP 安全上限の既定値は §3.2 で確定。 |
| <a id="o17"></a>O17 | 後続の非公開パッケージ | 旧 Issue #6 を別仕様として残すか、新 v1 の拡張版で設計するか。認証付き取得や権限・キャッシュ分離の仕様はここでは未定。 |

要件にあるサンプルは各形式の構造を示す。`METADATA.toml` には `./client` があるが `COMMANDS.json` にはないため、そのまま同一アーカイブに収録すると §3.5 で拒否される。さらに Sparse Index の `engines` は三ランタイム分、`METADATA.toml` は lnako のみで、`FILES.json` の長さ・ハッシュも別々の例示値。共同サンプルにする場合の修正は [フィクスチャ一覧](../fixtures/v1/conformance.md) の整合した入力を参照。
